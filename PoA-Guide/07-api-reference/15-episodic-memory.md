# Episodic Memory

Episodic Memory 计划记录 Agent 在任务中的观察、行动和结果，供后续任务查找与复用。本页说明七个 operator 的分工，以及它与 Working Memory 的关系。

---

## 1. 一段经历要留下什么

假设 Agent 排查一次登录失败：先重试，仍然失败；随后发现凭证过期，更新凭证后成功。只保存最后的“登录成功”，下一次遇到同类问题时就不知道此前的重试为什么没用。情景记录要保留这段经历中的观察、行动、反馈和状态变化，以及各步之间的先后与关联。

Working Memory 保存当前 Run 的结构化状态；[memory.snapshot](14-working-memory/07-snapshot.md) 描述如何捕获已提交状态。按当前规划，Episodic Memory 要把多次 WM 快照组织成经历的状态序列。情景记录还需要观察、行动和反馈等信息。快照是否包含这些信息，取决于此前写入 WM 的内容。

## 2. 七个 operator 分别做什么

下面按职责介绍七个 operator，不表示固定调用顺序。

设计中的元认知模块负责决定何时启用它们、采用什么方法，以及各自的计算和存储预算。

### `sense`

从交互和环境观测中识别一段经历，提取内容与时间等线索，并判断是否值得保留。

### `link`

为新旧经历建立先后、步骤间的因果、互补或冲突关系；新信息推翻旧信息时，保留更正关系。

### `activate`

判断当前 Working Memory 是否足够；需要回忆时，决定只做相似内容检索，还是沿某类关联继续查找。

### `remind`

按 `activate` 选定的方式找回相关经历，沿关联路径带出前置步骤或后续更正，在检索预算内选出有用的经历链。

### `contextualize`

把找回的经历按原有顺序，与当前任务状态和已发生的交互合在一起，供下一步决策使用；必要时参考长期知识。

### `act`

根据当前上下文生成并执行回复或行动，检查执行条件，并收集结果与反馈。

### `consolidate`

根据反馈修订经历及其关联，处理新旧信息冲突，并按需要提炼可复用知识或遗忘低价值内容。
