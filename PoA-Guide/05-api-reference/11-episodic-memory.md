# Episodic Memory

Episodic Memory 用于记录 Agent 在任务中的观察、行动和结果，供后续任务检索。本文介绍它与 Working Memory 的关系，以及七个 operator 各自负责的工作。当前没有可调用的 PoA API。

---

## 1. 一段经历要留下什么

一次登录失败的排查可能经历重试、发现凭证过期、更新凭证和重新登录。只保存最后的“登录成功”，下一次遇到同类问题时就无法解释此前的重试为何失败。经历记录需要保存观察、行动、反馈和状态变化，以及各步之间的先后与关联。

Working Memory 保存当前 Run 的结构化状态。Episodic Memory 需要把多个时点的 WM 状态组织成一段经历，并补充观察、行动和反馈等信息。当前 WM 作者面只能通过已登记 owner 读回和恢复整份数据，不能单独生成 Episodic Memory 记录。

---

## 2. 七个 operator 分别做什么

七个 operator 的职责如下，调用顺序由上层逻辑决定。

上层的元认知模块决定何时调用它们、采用什么方法，以及各自使用的计算和存储预算。

### `sense`

从交互和环境观测中识别一段经历，提取内容与时间等线索，并判断是否值得保留。

### `link`

为新旧经历建立先后、步骤间的因果、互补或冲突关系；新信息推翻旧信息时，保留更正关系。

### `activate`

判断当前 Working Memory 是否足够；需要回忆时，决定只做相似内容检索，还是沿某类关联继续查找。

### `remind`

按 `activate` 选定的方式找回相关经历，沿关联路径带出前置步骤或后续更正，在检索预算内选出有用的经历链。

### `contextualize`

把找回的经历按原有顺序，与当前任务状态和已发生的交互合并，作为下一步决策的上下文；必要时参考长期知识。

### `act`

根据当前上下文生成并执行回复或行动，检查执行条件，并收集结果与反馈。

### `consolidate`

根据反馈修订经历及其关联，处理新旧信息冲突，并按需要提炼可复用知识或遗忘低价值内容。

## 3. 当前的接入边界

七个 operator 尚无调用入口，也没有稳定的输入输出定义。
